## Closed contracts

The shared permission catalog currently contains one reserved dynamic entry:

```text
surface: claude_web
host: https://claude.ai:443/*
named permission: scripting
```

The public permission API accepts only the closed Claude scope and exposes typed
host, named-permission, registration, executable, port, and runtime-state
values. Raw permission arrays are confined to the background adapter boundary;
unknown permissions, origins, page-derived values, and extra metadata are
rejected. Runtime state is one of:

```text
permission_not_granted | adapter_disabled | adapter_waiting |
adapter_active | adapter_degraded | adapter_unsupported
```

The API wrapper is testable with mocked Chrome events. M2.1 does not call
`permissions.request()` from options, popup, content, or background startup. The
reserved Claude setting is persisted as disabled and cannot grant access.

## Settings V3 and Audit V4

Settings now contain the immutable configurable-surface order:

```json
[
  { "surfaceId": "chatgpt_web", "enabled": true },
  { "surfaceId": "claude_web", "enabled": false }
]
```

V1 and V2 settings migrate deterministically to V3 while preserving existing
policy values. Unknown fields, unknown or duplicate surface IDs, reordered
surface entries, and an enabled reserved Claude surface fail closed. Permission
state is never persisted.

M1 emitted the ChatGPT-only Audit V3 envelope. M2.1 migrated provable legacy V3
records to the current V4 envelope only when their legacy
`application: "chatgpt"` identity and contributor set were provable. Current
events carry catalog-owned `adapterId`, `surfaceId`, and `adapterVersion`;
ambiguous legacy identities are discarded. Clean allow decisions remain
minimized and retention behavior is unchanged.

## Verification

The M2.1 tests cover permission combinations, revocation and duplicate event
handling, closed-scope rejection, disabled surfaces, unavailable executables,
ChatGPT operation without `scripting`, settings migration, conservative surface
validation, V3-to-V4 audit migration, and inactive options copy.

The future M2.2 permission shape is documented and allowlisted for source
review, but the M2.1 generated artifact still rejected optional permissions,
Claude bundles, selectors, and dynamic registration. No browser permission
prompt or Claude executable code was part of M2.1. The M2.2 candidate's
automated evidence and provisional digest are recorded separately; no
authenticated Claude acceptance is established by this rollback document.

M2.2 is documented separately in

The M2.1 statements above describe the historical infrastructure commit and
remain the rollback target if the Claude candidate does not pass its merge gate.
