# M2.2 Claude verification candidate

Status: executable verification candidate; not authenticated production
acceptance.

M2.2 adds exactly one new application surface, Claude web, while preserving
ChatGPT's static entry and behavior. The Claude runtime remains explicitly
described as a **Claude verification candidate** in the popup and options page.
No local test, browser response, or runtime flag promotes it to accepted
production status.

The repository contains no approved-design provenance or authenticated
production-acceptance record for this candidate. Design documents remain
proposals, and any later production claim belongs to human/release metadata
bound to one exact CI artifact, SHA, and digest; it does not change this
candidate wording or rebuild the artifact.

## Closed runtime shape

| Field                   | Value                                      |
| ----------------------- | ------------------------------------------ |
| Application             | Claude web                                 |
| Exact adapter origin    | `https://claude.ai`                        |
| Adapter version         | `1`                                        |
| Content entry           | `content-claude.js`                        |
| Dynamic registration ID | `promptguard-claude-v1`                    |
| Registration match      | `https://claude.ai:443/*`                  |
| Frames/world/timing     | top frame, isolated world, `document_idle` |
| Persistence             | `persistAcrossSessions: true`              |

The optional permission request is one closed tuple: `scripting` plus
`https://claude.ai:443/*`. Host access alone, `scripting` alone, disabled Claude
settings, stale registration, and unavailable registration APIs do not authorize
the runtime. Permission state is live browser state and is never persisted in
settings or audit records.

Either permission-removal event invalidates the Claude runtime generation
synchronously, disconnects matching content ports, and rejects subsequent
status/audit claims before asynchronous registration cleanup. Removing Claude
access removes the exact host and named permission scopes. Dynamic named
permission cleanup is dependency-aware through the catalog-owned
`isScriptingStillRequired` check.

## Rollback

Rollback is a source-level removal of the M2.2 Claude executable surface:

1. Remove the Claude catalog descriptor and Claude-only registry/entry.
2. Remove `content-claude.js` from the build and exact dynamic registration.
3. Remove `scripting` and the Claude pattern from the generated manifest.
4. Remove the Claude grant/toggle UI and leave the shared M2.1 contracts
   disabled and inert.
5. Rebuild, rerun topology/artifact verification, and use the resulting
   ChatGPT-only digest. The known M2.1 rollback baseline is 12 files with digest
   `e4654d650fef9ed9d0e54e4900ff493a11ec93e017843dc95275e625d0d27424`.

No rollback path widens the origin pattern or enables unsupported replacement or
attachment inspection.
